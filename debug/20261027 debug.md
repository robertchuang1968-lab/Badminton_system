today = datetime.now()
year = today.year
full_date = f"{year}/{month}/{day}"

# 檢查場次是否過期
is_expired = False
try:
    target_date = datetime(year, int(month), int(day))
    if target_date.date() < today.date():
        is_expired = True
except:
    pass

# 回傳物件中包含新增欄位

## 3. Bug 診斷分析 (Root Cause Analysis)

為什麼輸入 `10/25 PM Vic +1` 卻產出了 **【批次報名結果】** 與 **「未開場」** 的回覆？

### 原因一：訊息走到了 `parse_registration_batch` 而非 `parse_registration`
從測試結果圖中帶有 `【批次報名結果】` 標頭可知，這則訊息在 `main.py` 中觸發了 **`parse_registration_batch()`（批次報名解析器）**，而不是單筆的 `parse_registration()`！
* **問題點**：您只在 `parse_registration()` 中新增了過期判定邏輯，但 `parse_registration_batch()` 中**並未寫入過期檢查邏輯**，導致產出的 `RegistrationData` 裡 `is_expired` 依然是預設值 `False`。

### 原因二：跨年份跨月邊界問題 (Edge Case)
在 `message_parser.py` 中直接取得 `year = today.year`：
* 如果當前時間是 10 月，報名 1 月的場次，年份若帶入當前年份（2026），會被判定為過期（2026/01 < 2026/10）。需要考慮跨跨年的年份算推邏輯。
